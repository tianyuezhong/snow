# 雪迹

一个手机优先的个人单板滑雪成长手账。使用 React、TypeScript 和 Vite，数据保存在当前设备的 IndexedDB 中。无需账号、后端、付费 API 或云端同步，不包含分析追踪，也不上传日记。

## 用 GitHub Pages 发布

准备一个独立的 **Public 仓库 `snow`**，将本项目的源码和生成的 `docs/` 放在仓库根目录。无需额外服务器环境，无需配置 Secrets，也无需编写 GitHub Actions 工作流。

在电脑上安装依赖并生成可直接发布的文件：

```bash
npm install
npm run prepare:pages
```

`prepare:pages` 会构建正式版本并生成 `docs/`。把项目源码和整个 `docs/` 目录一起提交、推送到 `main` 分支，然后在 GitHub 仓库中设置：

1. 打开 **Settings → Pages**。
2. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
3. 在 **Branch** 选择 **main**，文件夹选择 **/docs**，点击 **Save**。
4. 等待 GitHub Pages 完成发布，使用 Pages 设置页显示的网址访问。账号为 `tianyuezhong`、仓库为 `snow` 时，默认地址通常是 `https://tianyuezhong.github.io/snow/`。

以上是发布操作说明，不表示仓库已上传或网站已上线。日后更新代码时，再运行 `npm run prepare:pages`，把更新后的源码和 `docs/` 一起推送即可；手机上的更新方式见下文。

Public 仓库公开的是应用源码和静态文件。你的滑雪日记、个人档案与装备记录仍只保存在各自设备的 IndexedDB，应用不会把它们上传到 GitHub。导出的个人 JSON 备份请另行保存，不要提交到公开仓库。每位朋友打开同一个网站，保存的仍是各自设备上的独立数据。

## 第一版功能

- **今天滑雪**：选择日期、雪场、雪况、地形、精力和信心；选择最多两个训练目标，按技能直接匹配练习卡；替换、移除或添加自定义练习；标记「未练／已尝试／继续练」，支持大字模式。编辑中的记录自动保存为草稿，重新打开后可继续。
- **滑雪日记**：新建、查看、修改、确认后删除记录；按雪场、技能和日期筛选。日期和雪场必填，快速复盘、时长、反馈、身体感受、装备感受与视频备注均可选填。同一天可以保存多篇日记。
- **技能成长**：内置四类单板技能，也可添加自定义技能。查看前置能力、相关练习和日记，手动确认四级自评并保留变化日期。练习次数不会自动改变自评，高阶动作以准备和教练指导为主。
- **我的雪季**：设置雪季起止日期、最多三个目标、个人档案和多套装备；查看不同日期的滑雪天数、已填总时长、雪场和练习分布。日记保存装备快照，后来修改或删除装备档案不会改写历史快照。
- **本地备份**：导出完整 JSON，导入前校验版本和结构，显示备份日期与记录数量；确认后替换全部数据，支持先导出当前数据。错误文件不会进入替换流程。显示上次导出时间，新增多篇记录后温和提醒备份。
- **PWA**：包含应用图标、manifest 和 Service Worker。生产版本首次联网加载并成功缓存后，可离线打开核心页面、查看内置练习和保存本地记录。

初始记录为空，不包含虚构成绩或私人信息。练习是一般参考，并非官方教练课程或认证标准；请在能力范围内练习，复杂地形和跳跃可寻求教练指导。

## 在电脑上运行

先安装 Node.js 22 LTS，然后用终端进入本项目目录：

```bash
cd /workspace/xueji
npm install
npm run dev
```

打开终端显示的本地地址，通常是 `http://localhost:5173`。修改源码后页面会自动更新。停止运行时，在终端按 `Ctrl+C`。

如果项目保存在你电脑的其他位置，请把 `cd` 后面的路径换成实际路径。开发服务器会监听局域网地址；手机和电脑连接同一个 Wi-Fi 后，可以打开终端中的 Network 地址检查布局。普通局域网 HTTP 不具备完整 PWA 条件，不能用它验收 iPhone 离线功能。

运行关键逻辑测试：

```bash
npm test
```

测试文件覆盖日期统计、IndexedDB 新建修改删除与重新读取、备份校验及恢复、装备快照、练习与技能关联。IndexedDB 测试使用 `fake-indexeddb`，不能替代真实 Safari 的存储验证。是否通过请以实际命令输出为准。

构建并预览正式版本：

```bash
npm run build
npm run preview
```

构建会先检查 TypeScript，再生成 `dist/`，最后把正式资源列表和版本标识写入 `dist/sw.js`。打开预览地址，通常是 `http://localhost:4173`。Service Worker 只在正式构建中注册，`npm run dev` 不用于离线验收。`localhost` 可用于电脑上的 Service Worker 测试。

## 部署为静态网站

本项目不需要服务器程序或数据库，也没有自动发布步骤。部署时自行选择支持 **HTTPS** 的静态网站托管，上传 `npm run build` 生成的 **`dist/` 目录内全部文件**，保持文件名和目录结构不变。不要只上传 `index.html`，也不要直接上传 `src/`。

如果托管平台询问构建设置：

| 设置 | 填写内容 |
| --- | --- |
| 项目根目录 | `xueji` 所在目录 |
| 安装命令 | `npm install` |
| 构建命令 | `npm run build` |
| 发布目录 | `dist` |
| Node.js | 22 LTS |

Vite 使用相对资源路径，可部署到静态目录。本应用使用页面内导航，不需要配置服务端路由。正式地址须能访问 `index.html`、`manifest.webmanifest`、`sw.js`、图标和 `assets/`；建议让 `sw.js` 每次检查更新，避免给它设置长期不变的强缓存。

部署新版本前先导出备份。新版本的 Service Worker 通常需要等待旧页面关闭后接管；请关闭这个站点的所有标签页和主屏幕应用窗口，再联网重新打开。更新代码不会主动清空 IndexedDB。更换域名、协议或端口会进入另一份浏览器存储，请用 JSON 备份搬迁数据。

## 添加到 iPhone 主屏幕

1. 用 iPhone 的 **Safari** 打开部署后的 HTTPS 地址，首次保持联网。
2. 等待页面正常加载，在「我的雪季 → 本地数据与备份」查看离线缓存提示。
3. 点击 Safari 的分享按钮，选择「添加到主屏幕」，确认名称「雪迹」。
4. 从主屏幕打开应用，先保存一篇测试记录并重新打开，确认记录仍在。
5. 再开启飞行模式，关闭并重新打开应用，检查页面、练习卡和记录保存。

缓存状态提示表示浏览器已完成相关注册或激活流程，仍应实际断网验证。Safari 标签页与主屏幕应用是否共用已有数据会受到 iOS 版本和使用方式影响，请以安装后的实测为准；需要时用备份导入。不要假定另一浏览器、另一设备或另一个网址会自动出现相同记录。

## 数据保存在何处，怎样备份

数据存于当前浏览器、当前网站来源的 IndexedDB：数据库 `xueji-local`，对象仓库 `data`。页面编辑会自动提交保存；写入失败会显示提示，并提供重试和导出按钮。编辑草稿与正式日记分开，点击「保存到滑雪日记」后才计入正式记录。完成写入以页面显示「已保存在此设备」为准。

**数据仅保存在此设备，建议定期备份。** 清除网站数据、浏览器回收存储、隐私模式结束、设备损坏或更换设备，都可能导致数据不可用。「请求浏览器保留本地数据」只是请求浏览器尽量保留，不能保证数据永远不丢失。

导出备份：

1. 打开「我的雪季 → 本地数据与备份」。
2. 点击「导出完整 JSON 备份」。
3. 确认下载完成，把文件保存到 iPhone 的「文件」App 或电脑的可靠位置。备份包含档案、日记、草稿、技能自评、自定义技能、装备、雪季和设置，也包含数据版本与导出时间。

导出时间记录的是应用发起导出的时间；应用无法确认你是否最终保留了文件，请自行检查。JSON 文件包含个人记录，分享前请确认内容。

恢复备份：

1. 点击「从备份恢复」，选择雪迹导出的 JSON 文件（最大 20 MB）。
2. 应用先校验结构与版本；失败时显示错误，原数据保持不变。
3. 阅读备份日期、日记数量和装备数量。需要保留现有数据时，点击「先导出当前数据」。
4. 确认下载后再点击「确认替换并恢复」。此操作替换全部雪迹数据，**不会合并**；取消则不替换。

备份导出是文件保存，不是云端同步。另一台设备要继续使用，需自行传输文件并导入，之后两台设备的数据仍各自独立。

## 验收与限制

建议先用测试记录验收，再开始记录真实雪季。下列浏览器和真机项目需要在目标设备实际操作；仅有源码或 Node.js 测试不能说明它们已通过：

- 新建记录、修改内容、确认删除；刷新或退出重开后检查结果。
- 开始一篇未完成的记录，退出后通过「继续今天的滑雪」恢复草稿。
- 同一天保存两篇，确认累计只算一天；修改雪季范围，确认范围外记录不计入。
- 为记录选择装备，保存后修改装备档案，再查看旧记录的快照。
- 导出 JSON，恢复后检查内容；尝试错误 JSON，确认原数据不受影响。
- 正式版本首次联网缓存成功后断网，重开页面、查看练习、新增记录；恢复联网后确认数据仍在。
- 在真实 iPhone 上检查主屏幕安装、离线冷启动、软键盘、日期输入、文件下载与导入、安全区域和底部导航。
- 在较窄手机屏幕上逐页检查，确认无横向溢出，弹窗和长练习卡能够滚动，按钮可点击。
- 部署更新版本，关闭旧标签及主屏幕窗口后重开，确认代码更新且旧记录仍在。

第一版未包含账号、云同步、社交、排行榜、GPS、实时天气雪况、AI 视频点评、视频文件存储、付费或预算功能。自定义技能可关联自定义练习，但不会自动生成教学内容。

## 代码位置

| 文件 | 用途 |
| --- | --- |
| `src/main.tsx` | 四个页面、记录编辑、备份与恢复交互 |
| `src/library.ts` | 内置技能、练习内容及明确的匹配规则，更新练习优先改这里 |
| `src/core.ts` | 数据类型、IndexedDB、备份校验、版本入口与统计 |
| `src/core.test.ts` | 数据和关键逻辑测试 |
| `src/style.css` | 手机布局、桌面适配和大字模式 |
| `public/manifest.webmanifest` | PWA 名称、图标和启动设置 |
| `public/sw.js`、`scripts/build-sw.mjs` | Service Worker 模板及构建时离线资源清单 |

当前数据版本为 `1`，通过 `migrate()` 统一读取；不支持的版本会报错并保留存储，不会自动清空。未来改变结构时，需要在该入口编写并测试迁移，再提高版本号，不能直接替换旧数据。
